# Производительность и дополнительные возможности

## Измеренная производительность

Окружение: macOS ARM64, Docker Desktop Linux ARM64, 8 CPU и 3,825 GiB RAM
для Engine; браузер Chrome. Данные относятся к зафиксированной сборке
от 26 сентября 2026 года; изменения пакета сдачи затрагивают документацию.

| Проверка | Результат |
|---|---|
| Холодный старт с новой БД до настоящего прогноза в браузере, 3 запуска | 18,748–19,220 с; максимум 19,220 с |
| 100 ТС, полная 15-минутная история, обычный поток 100 событий/с | расчёт → React p95 **542 мс**; получение телеметрии → React p95 **1209 мс** |
| Сверка обработки после короткой диагностики | **102 000 raw = inbox = applied = checkpoint**, pending=0 |
| Восстановление PostgreSQL после отключения на 30 с | полная сверка накопленных событий прямым SQL за **1,170 с** |
| Исходные CSV → настоящий NDTP → модель → браузер, 60 с | 102 пакета; первый прогноз на UI за **3,646 с** |
| Поставленный NDTP-эмулятор → оценка отклонения → модель → браузер | **28,442 с**, включая накопление наблюдений сценария |
| Отказы NDTP, ML, PostgreSQL, аварийное пересоздание Backend | проверки пройдены |

История для теста 100 ТС загружалась за 180 с, затем 120 с шёл обычный поток;
400 новых модельных прогнозов подтверждены в браузере. Это **короткая диагностика**,
а не часовая приёмка. Подробные измерения и версии образов:
[сводный отчёт](artifacts/acceptance/summary.json), [протокол](docs/validation.md).

Сборка/скачивание Docker-образов и обучение моделей не входят во время холодного
старта. Часовая устойчивость, два длительных всплеска и плато памяти окончательно
не подтверждены: прогон отложен по указанию пользователя. Человеческий тест
понятности интерфейса за 5 секунд не проведён.

## Точность и готовность модели

- Official: MAE **70,612 с** на 353 test-точках против 103,337 с у нулевого
  baseline и 93,360 с при переносе предоставленного текущего отклонения.
- Stream: MAE **80,576 с** на всех 353 контрольных точках; **81,580 с**
  на 340 свежих, ещё не посещённых целях. Признаки рассчитываются причинно.
- Test и validate относятся к одному периоду; скрытый MAE и качество новых дней
  не измерены. Official-метрику нельзя обещать для живого потока.
- Поиск 50 конфигураций CatBoost не прошёл принятый порог подтверждения;
  исходная модель сохранена. [Результат настройки](docs/tuning.md).

## Реализованные дополнительные возможности

- Версионированный импорт JSON-сценариев: планы, привязки устройств, остановки,
  маршруты и направленная геометрия; предварительная проверка без сохранения.
- Исторический replay с паузой и скоростями ×1/×5/×20; отдельная ретроспективная
  оценка; NDTP-демо с проверяемым переносом исходного времени на текущую дату.
- Вся маршрутная сеть, поиск и фильтрация ТС, карточка точного инцидента,
  сохранённый ACK, история скорости и прогнозов, адаптация под узкий экран.
- Вероятность опоздания, плановое и ожидаемое прибытие, SHAP-факторы и гипотезы
  причин. Схематичная и импортированная геометрия явно различаются.
- SSE с переподключением и защитой от устаревших ответов, резервный опрос API.
- Долговечный PostgreSQL inbox, пакетная обработка, ограниченные очереди,
  дедупликация, восстановление checkpoint и управление сроком хранения.
- Явное устаревание данных и baseline при недоступном ML без вымышленной вероятности.
- Раздельные времена данных, расчёта и публикации; повторная проверка горизонта
  после расчёта и записи в БД, подавление предупреждений задним числом.
- Healthcheck, Prometheus-метрики, OpenAPI обоих API, Sphinx по коду и
  автоматическая публикация документации через GitHub Actions.
