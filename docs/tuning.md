# Настройка CatBoost для официального профиля

Процедура ищет улучшение MAE официального регрессора и проверяет его по заранее
зафиксированным правилам. Первый поиск завершён: выигрыш не достиг порога
подтверждения; измерения приведены в конце этой страницы.
Потоковый профиль `stream`, работающие сервисы и часовой нагрузочный тест
в эту процедуру не входят.

## Запуск и область изменений

После установки зависимостей выполните из корня репозитория:

```bash
.venv/bin/python -m ml.tune \
  --data-dir dataset \
  --baseline-model-dir artifacts/models \
  --output-dir artifacts/tuning/official-20260927-01 \
  --trials 50 \
  --seed 20260926
```

Для каждого запуска используйте отдельный каталог `artifacts/tuning/<run_id>`.
`--trials 50` означает 50 конфигураций, а не 50 обучений: только первый этап
требует около 200 fit-вызовов, затем добавляются проверки seed и подтверждение;
полная процедура включает более 200 обучений.
CatBoost работает на CPU с двумя потоками; первый полный поиск занял 195,80 с
на описанном в отчёте окружении. На другом компьютере время может отличаться.

Меняются только гиперпараметры регрессора профиля `official`. Используются
те же 55 признаков схемы `1.0.0` и 1141 реальная train-точка. Синтетические
ТС с ID 9 000 000–9 999 999 исключаются. Признаки, состав обучающей выборки
и способ восстановления отклонения остаются фиксированными:

```text
residual_target = target_delay_s - fillna(cur_dev_s, 0)
prediction_delay_s = predicted_residual + fillna(cur_dev_s, 0)
```

Классификатор вероятности опоздания более чем на 120 секунд и его калибровка
копируются из исходного bundle без переобучения. Улучшение MAE регрессора
само по себе не означает улучшения Brier или точности вероятностей.

## Защита временных границ

Используются три существующих хронологических fold из `ml.train.temporal_folds`.
Начала validation-окон соответствуют квантилям времени 0,45 / 0,63 / 0,81.
Первые два fold служат поиску; третий закрыт для него и открывается один раз
для оценки нового кандидата после его фиксации. Результат исходного контроля
на третьем fold может воспроизводиться заранее, но не участвует в ранжировании
конфигураций.

На каждой границе обучение заканчивается за 30 минут до validation. Из него
исключаются целевые посещения validation-части; фактические исходы обучающих
примеров должны стать известны до границы отсечения. Эти же ограничения
применяются к внутреннему разделению для early stopping. Признаки по-прежнему
строятся только из телеметрии с `event_time <= T`; будущие фактические прибытия
и целевые колонки не попадают в признаки.

Временные fold не являются новыми независимыми днями. Третий fold уже входил
в прежнее обучение и отчёт: его роль здесь — отдельное подтверждение нового
выбора, а не ранее неизвестный период. Известный test-score также не превращает
test в новый независимый набор.

## Поиск и фиксация числа деревьев

В 50 конфигураций входят контроль с исходными 400 деревьями, исходные параметры
с подбором числа деревьев и 48 уникальных комбинаций из пространства ниже.
Выбор комбинаций воспроизводится seed 20260926. Loss — MAE, bootstrap — MVS.

| Параметр | Допустимые значения |
|---|---|
| `depth` | 3, 4, 5, 6, 7 |
| `learning_rate` | 0,02; 0,03; 0,045; 0,07; 0,1 |
| `l2_leaf_reg` | 1, 3, 5, 10, 20 |
| `random_strength` | 0; 0,5; 1; 2 |
| `subsample` | 0,6; 0,8; 1 |

Для каждой из 49 настраиваемых конфигураций на каждом из первых двух fold:

1. Только его train-часть делится хронологически: первые 80% — внутреннее
   обучение, последние 20% — early stopping, с тем же purge 30 минут.
2. Обучается residual-регрессор: максимум 2000 итераций, patience 100.
   Внешнее validation-окно не используется для выбора числа деревьев.
3. Полученное число деревьев фиксируется; регрессор заново обучается на всей
   допустимой внешней train-части и оценивается на внешнем validation.

Рейтинг формируется только по первым двум fold: MAE объединяет их ошибки
с весом по числу validation-точек. Контроль сохраняет исходные 400 деревьев
и не использует early stopping. Исходная конфигурация
сравнивается на тех же временных разбиениях после обучения на соответствующих
train-частях. Загруженный регрессор, обученный на всех train-точках, не служит
baseline для оценки этих fold.

## Правила принятия

Три лучших настраиваемых конфигурации проверяются с seed **20260926, 20260927 и 20260928**
на тех же двух fold. У кандидата должны одновременно выполняться условия:

- средний по трём seed выигрыш MAE двух fold, взвешенный по числу точек,
  относительно baseline — не менее **1 секунды**;
- средняя по seed ошибка каждого из двух fold не хуже baseline;
- минимум два из трёх seed дают выигрыш относительно baseline.

При численно равных средних MAE (точность 1e-9 с) предпочтение отдаётся меньшей глубине,
затем меньшей медиане числа деревьев. Для выбранного кандидата число деревьев
фиксируется округлённой до целого медианой шести значений,
полученных для двух fold и трёх seed. После этого замораживаются гиперпараметры,
число деревьев, схема признаков и seed **20260926**.

Новый кандидат оценивается на третьем fold ровно один раз: замороженный
кандидат должен улучшить MAE baseline минимум на **1 секунду**. Он не используется
для early stopping, смены параметров или выбора другого кандидата. Если ни один
кандидат не прошёл seed-проверки или выбранный кандидат не прошёл подтверждение,
поиск заканчивается без выпуска замены. Новый поиск в ответ на неудачное
подтверждение не запускается.

## Финальная оценка и отдельный bundle

После успешного подтверждения замороженный регрессор обучается на всех
1141 реальных train-точках с фиксированным числом деревьев и seed 20260926.
Test читается для оценки только после фиксации модели. Его результат записывается
в отчёт; изменение параметров или повторный поиск по test-ошибке запрещены.
Даже успешное train-подтверждение не гарантирует улучшение test MAE.

Результаты сохраняются внутри каталога запуска:

| Файл | Назначение |
|---|---|
| `configs.json`, `splits.json` | Конфигурации и зафиксированные разбиения |
| `provenance.json` | Версии библиотек, хеши исходников и матрицы признаков, фактические параметры контрольной модели |
| `control.json`, `results.json` | Контроль и накапливаемые результаты попыток |
| `oof/<config_id>/seed-<seed>.csv` | Прогнозы на внешних validation-окнах |
| `finalist.json` | Кандидат, замороженный до своей оценки на третьем fold |
| `confirmation_attempt.json`, `confirmation.json`, `confirmation_predictions.csv` | Фиксация единственной попытки, её результат и прогнозы третьего fold |
| `report.json`, `integrity.json` | Итоговое решение и проверка сохранности исходных артефактов |
| `models/` | После подтверждения: `regressor.cbm`, `classifier.cbm`, `manifest.json` |
| `export_verification.json` | Проверка прогнозов после сохранения и неизменности классификатора и калибровки |
| `test_report.json`, `test_predictions.csv`, `submission.csv` | После подтверждения: test-оценка и отдельная validate-подача |

В отчёте различаются `RUNNING`, `NO_CONFIRMED_IMPROVEMENT`,
`CONFIRMED_IMPROVEMENT`, `FAILED` и `INTERRUPTED`. Подтверждённое улучшение относится к
train-протоколу принятия; это не обещание выигрыша на test и не автоматическое
внедрение. Если кандидат не прошёл правила, модель и submission не выпускаются.

Исходные `artifacts/models/`, `artifacts/submission.csv`
и `artifacts/models/stream/` не заменяются.
Новый bundle содержит обученный регрессор, неизменённый классификатор
и прежние параметры калибровки; это кандидат для последующего явного внедрения.

Submission сохраняет формат организаторов: UTF-8, разделитель `;`, ровно
`sample_id;prediction`, каждый из 151 validate-ID один раз, конечные подписанные
секунды в порядке шаблона. При его построении используются validate-точки,
телеметрия и план; восстанавливать ответы из пересекающихся расписаний с фактами
нельзя.

Метрики относятся к официальному протоколу с предоставленным `cur_dev_s`.
Test и validate используют телеметрию одного периода; результат не подтверждает
качество новых дней или живого `stream`-профиля. Текущие измеренные результаты
и их границы остаются в [протоколе проверки](validation.md).

## Результат запуска 27 сентября 2026 года

Запуск `official-20260927-01` завершился со статусом
`NO_CONFIRMED_IMPROVEMENT`. Все 50 конфигураций проверены без ошибок обучения;
с повторами получено 58 оценок и выполнено 228 fit-вызовов за 195,80 с.
Контроль точно воспроизвёл исходные метрики: максимальное расхождение 0 с.

| Этап | Контроль, MAE с | Финалист, MAE с | Выигрыш, с |
|---|---:|---:|---:|
| Первые два разбиения, среднее по трём seed | 72,293 | 70,650 | 1,644 |
| Третье разбиение, единственная проверка | 88,940 | 88,823 | 0,117 |

Финалист `trial_036`: глубина 5, learning rate 0,1, L2 20,
random strength 0, subsample 0,8, MVS, 89 деревьев, seed 20260926.
Он улучшил оба первых разбиения в среднем и выиграл при всех трёх seed.
Однако выигрыш на третьем разбиении меньше принятого минимума 1 с.
Другие кандидаты на третьем разбиении не проверялись; порог не снижался.

Новая модель и новый submission не выпущены. Оценка на test и inference на
validate не выполнялись. Контрольные суммы исходных данных, действующих моделей
и текущего submission сохранились. Все **180 Python-тестов** прошли, включая
17 новых тестов настройки; предупреждение Starlette осталось прежним.
