# Проверка реализации

Результаты получены 26 сентября 2026 года на локальном Docker Desktop
(Linux ARM64, 8 доступных CPU, 3,825 GiB RAM для Docker). ML работает на CPU;
поставляемый NDTP-эмулятор запускается как Linux AMD64. Исходные CSV не изменялись.

## Функциональные проверки

| Проверка | Результат | Подтверждение |
|---|---|---|
| Python: признаки, ML, Backend, replay, NDTP | 40 тестов прошли | `python -m pytest -q` |
| HTTP-путь и совпадение online/offline официальной точки | 12 проверок прошли | `artifacts/smoke.json` |
| Браузер: replay, выбор ТС, поиск, 390 px, отказ тайлов | 5 проверок, без JavaScript-ошибок | `artifacts/ui_check.json` |
| Перезапуск Backend, отказ и восстановление ML | 3 проверки прошли | `artifacts/resilience_check.json` |
| Реальный NDTP-эмулятор | Handshake, 3 события, верные координаты и скорость | `artifacts/ndtp_check.json` |
| Frontend | Production build выполнен в Docker | `frontend/Dockerfile` |
| Документация | Sphinx `-W` собирается без предупреждений | `docs/_build/html/index.html` |
| Submission | 151 уникальный ID, исходный порядок, конечные числа | `artifacts/data_integrity.json` |

Тесты проверяют неизменность признаков при добавлении будущих событий и
фактических прибытий, временные разбиения, границы горизонта, пропуски,
разделение TCP-кадров, CRC, reconnect, ошибки БД, изоляцию прогонов,
восстановление последних позиций и отсутствие повторных посещений при стоянке.

Программный HTTP-тест также подтверждает работу OpenAPI, SSE reset при
недоступном курсоре, pause/resume и подтверждение просмотра инцидента.

В тестовом окружении есть предупреждение Starlette о будущей замене транспорта
TestClient `httpx`; все проверки проходят. Это не ошибка рабочего HTTP-сервиса.

## Качество модели

| Протокол | Примеры | MAE, с |
|---|---:|---:|
| Нулевой baseline на test | 353 | 103,34 |
| Предоставленный `cur_dev_s` | 353 | 93,36 |
| Выпущенная CatBoost-модель, официальный протокол | 353 | **70,61** |
| Та же модель, получение событий по receive_time и оценённый `cur_dev_s` | 353 | **196,86** |
| Последний режим, только свежая телеметрия | 350 | **196,96** |

Официальный test Brier score: 0,1274. Вероятность относится к событию
`target_delay_s > 120 с`. Калибровочная диаграмма находится в
`artifacts/calibration.png`, подробные разрезы — в `artifacts/report.json`.

Модель выбрана по временным train-разбиениям и не перенастраивалась по
online-оценке. В последней восстановленное отклонение доступно для 300 из
353 точек; его среднее абсолютное расхождение с предоставленной подсказкой
составляет 203,61 с. Это существенное ограничение эвристического сопоставления.
Официальные 70,61 с нельзя обещать диспетчеру в непрерывном режиме.

Набор содержит один основной период, test и validate имеют одинаковую
телеметрию. Для вывода о новых днях нужны независимые данные. MAE_TARGET
организатора не задан, скрытый score платформы не рассчитывался.

## Производительность и восстановление

Последний прогон: диспетчерский режим ×20, 60 секунд реального времени,
примерно 20 минут виртуального. Измерения: `artifacts/benchmark.json` и
`artifacts/benchmark.prom`.

- Запуск прогретого replay через HTTP: 0,57 с.
- Ответ `/snapshot`: p50 6,59 мс, p95 49,82 мс; 59 измерений.
- Скользящий p95 Backend для расчёта и сохранения пакета прогнозов: 339,79 мс.
  Он охватывает до 1000 последних циклов процесса, включая предшествующие прогоны.
- За интервал между первым и последним снимками добавлены 2014 событий
  телеметрии и 298 прогнозов. Ошибок ML и NDTP в этом прогоне нет.
- Одновременно наблюдалось не более 9 заданий в текущем пакете; в конце — 0.
  По этому короткому прогону накопления заданий не обнаружено.
- Backend восстановил сохранённое состояние после рестарта за 3,27 с.
  Это запуск с готовым образом и существующей БД, без загрузки зависимостей.

Снимок памяти во время проверки: Backend около 196 MiB, ML 149 MiB,
PostgreSQL 46 MiB, Nginx 11 MiB; отдельно эмулятор около 294 MiB.
Это наблюдение, а не измеренный максимум или гарантия ёмкости сервера.

Период планового пересчёта составляет 30 секунд виртуального/реального времени
в зависимости от режима. Показатели HTTP и времени обработки не включают
ожидание этого периода и не являются полной задержкой от GPS до экрана.
Обновления SSE публикуются примерно раз в секунду. Полномасштабный нагрузочный
тест на городской парк не проводился.

## Артефакты и ограничения демонстрации

- `artifacts/submission.csv`: все 151 точки validate; 42 отрицательных прогноза
  сохранены как допустимое опережение, пропусков и дублей нет.
- `artifacts/models/manifest.json`: версия, параметры, схема, зависимости
  и контрольные суммы обучающих входов.
- `artifacts/screenshots/dashboard-desktop.png` и `dashboard-mobile.png`:
  реальные данные работающего приложения.
- Реальный NDTP проверяется отдельно: его часы сегодняшние, расписание —
  январское. Для прогноза в таком потоке потребуется актуальное расписание.
- Точный маршрут, причины сбоев и дверные события в данных отсутствуют.
  Карта показывает схему остановок, объяснения — гипотезы и модельные факторы.

Команды воспроизведения приведены в README. Контрольные скрипты начинают новые
прогоны; resilience-скрипт временно останавливает ML и всегда восстанавливает его.
