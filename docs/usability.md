# Проверка понятности за пять секунд

**Статус: NOT_RUN — участники ещё не проходили проверку.** Браузерные тесты подтверждают отображение и работу интерфейса, но не заменяют исследование с людьми.

## Материалы и подготовка

Команда `npm --prefix frontend run build`, затем `.venv/bin/python scripts/check_ui_regressions.py` создаёт три фиксированных экрана 1366×768 в `artifacts/usability/screens/`: `high-risk.png`, `multiple-risks.png`, `stale.png`. Это явно синтетические сценарии для проверки интерфейса. Рабочий Backend и текущий прогон не используются.

Пригласите минимум пять людей, не участвовавших в разработке. Запишите только обезличенный ID участника. Проводящий тест видит `artifacts/usability/answer_key.json`; участникам этот файл и подписи с ответами не показываются. `artifacts/usability/results.csv` содержит пустой шаблон, а не результаты.

## Процедура

1. Используйте обычный масштаб 100%, экран не меньше 1366×768. До начала скажите только: «За пять секунд определите транспорт и участки, требующие внимания из-за высокого риска задержки. Отдельно отметьте, где нет актуальных данных. Называйте ответ, пока экран виден». Не объясняйте расположение элементов или цветовую легенду.
2. Покажите каждый экран ровно на пять секунд, затем скройте. Порядок трёх экранов меняйте между участниками. Не разрешайте предварительное знакомство и не сообщайте правильные ответы до конца.
3. Во время показа запишите названные номера ТС и участки «от — до». Для экрана stale участник также должен указать, что прежняя вероятность не является текущей, и назвать ТС с устаревшими данными. Уточнения после скрытия экрана сохраняйте отдельно; они не засчитываются как распознавание за пять секунд.
4. Запишите ответ дословно, правильность по отдельному ключу и длительность показа. Если ответ получен только после пяти секунд, не засчитывайте своевременное распознавание. Замените строку `NOT_RUN` фактическими строками с `status=OBSERVED`; не заполняйте результаты предположениями.

## Критерий приёмки и отчёт

На каждом из трёх экранов минимум четыре из пяти участников должны за пять секунд правильно назвать высокорисковые ТС и участки. Для stale не допускается принятие устаревшей вероятности за текущую. При большем числе участников порог — 80% на каждом экране.

В отчёт включите дату, число участников, порядок экранов, ответы и долю успешных распознаваний по каждому сценарию. Скриншоты закрепляют проверенную версию интерфейса. До получения реальных ответов критерий остаётся **не подтверждён**. После изменения расположения ключевых полей проверку нужно повторить с новыми участниками.
